# aerial-signage

`aerial-signage` turns a Raspberry Pi 4 or 5 into a fullscreen Apple Aerial video loop with a configurable offset clock overlay. It mirrors the macOS Aerial fork behavior where `AERIAL_CLOCK_OFFSET_MINUTES` is added to the real time before display, defaulting to +10 minutes.

## Why HEVC

The default quality is `1080-sdr`, which uses HEVC. Both Raspberry Pi 4 and Raspberry Pi 5 hardware-decode 4K HEVC. Raspberry Pi 5 has no H.264 hardware decode, and Raspberry Pi 4 only hardware-decodes H.264 up to 1080p, so HEVC is the best default for this kiosk.

## Quick Start

```bash
sudo ./install.sh
sudo editor /etc/aerial-signage/aerial-signage.conf
sudo -u "$USER" AERIAL_CONFIG=/etc/aerial-signage/aerial-signage.conf /opt/aerial-signage/bin/aerial-fetch --limit 10
sudo reboot
```

Set `AERIAL_CLOCK_OFFSET_MINUTES` for the displayed time offset. Use a small `--limit` during setup because each video is large.

## Configuration

The config file is shell `KEY=VALUE` format. The installed path is `/etc/aerial-signage/aerial-signage.conf`.

| Variable | Meaning | Default |
| --- | --- | --- |
| `AERIAL_CLOCK_ENABLED` | `1` shows the clock, `0` hides it. | `1` |
| `AERIAL_CLOCK_OFFSET_MINUTES` | Minutes added to real time; negative values are allowed. | `10` |
| `AERIAL_CLOCK_FORMAT` | `24h`, `12h`, or `custom`. | `24h` |
| `AERIAL_CLOCK_SECONDS` | `1` shows seconds. | `0` |
| `AERIAL_CLOCK_HIDE_AMPM` | `1` hides AM/PM in `12h` mode. | `0` |
| `AERIAL_CLOCK_CUSTOM_FORMAT` | `strftime` string for `custom` mode. | `%H:%M` |
| `AERIAL_CLOCK_CORNER` | `topLeft`, `topRight`, `bottomLeft`, `bottomRight`, or `center`. | `bottomRight` |
| `AERIAL_CLOCK_FONT_SIZE` | ASS font size at 1920x1080 reference resolution. | `48` |
| `AERIAL_CLOCK_FONT` | Optional font family; empty uses mpv default. | empty |
| `AERIAL_CLOCK_MARGIN` | Pixel margin at 1920x1080 reference resolution. | `60` |
| `AERIAL_CLOCK_COLOR` | Clock color as `RRGGBB`. | `FFFFFF` |
| `AERIAL_QUALITY` | `1080-sdr`, `1080-hdr`, `4k-sdr`, `4k-hdr`, or `1080-h264`. | `1080-sdr` |
| `AERIAL_MANIFEST_URL` | JSON manifest URL. | Apple Aerial set (`sylvan.apple.com`) |
| `AERIAL_CACHE_DIR` | Directory for downloaded `.mov` files. | `/var/lib/aerial-signage/videos` |
| `AERIAL_PLAYLIST` | mpv playlist path generated by `aerial-fetch`. | `/var/lib/aerial-signage/playlist.txt` |
| `AERIAL_VIDEO_LIMIT` | `0` downloads all selected videos; `N` limits to first `N`. | `0` |
| `AERIAL_STRICT_QUALITY` | `1` = only the exact `AERIAL_QUALITY` variant, never fall back to another codec (use on Pi 3). | `0` |
| `AERIAL_SHUFFLE` | `1` shuffles the playlist. | `1` |
| `AERIAL_MPV_VO` | mpv video output. | `gpu` |
| `AERIAL_MPV_GPU_CONTEXT` | `drm` for Pi console; use `auto` for desktop testing. | `drm` |
| `AERIAL_MPV_HWDEC` | `drm-copy` for Pi HEVC hardware decode; use `auto` for desktop testing. | `drm-copy` |
| `AERIAL_MPV_EXTRA` | Extra raw mpv flags. | empty |

## Raspberry Pi 3 (experimental)

Pi 3 (VideoCore IV) has **no HEVC hardware decode**, its H.264 hardware decode tops out at 1080p,
its HDMI output is 1080p-only, and its CPU cannot software-decode HEVC in real time. The default
HEVC quality therefore cannot work. Use the H.264 set instead, in strict mode so no video silently
falls back to HEVC:

```
AERIAL_QUALITY=1080-h264
AERIAL_STRICT_QUALITY=1
AERIAL_MPV_HWDEC=v4l2m2m-copy
```

Notes: 1 GB RAM is enough with Raspberry Pi OS **Lite**; use a heatsink for 24/7 decoding. The
`v4l2m2m` H.264 path on Bookworm has not been validated on real Pi 3 hardware yet — treat this as
experimental and prefer a Pi 4/5 for new purchases.

## Video source

By default `aerial-fetch` downloads the real Apple Aerial set (63 videos, streamed from
`sylvan.apple.com`) via a community-maintained manifest mirror. A snapshot of that manifest is
bundled under `manifest/entries.json` and used automatically if the mirror is unreachable.

**Apple Root CA (Linux):** `sylvan.apple.com` is signed by Apple's *private* root CA, which ships on
macOS/iOS/tvOS but is absent from Linux trust stores — so downloads otherwise fail with
`CERTIFICATE_VERIFY_FAILED: unable to get local issuer certificate`. `install.sh` installs that root
automatically (fetched from Apple over a public-CA-verified connection and pinned by SHA-256); pass
`--no-apple-ca` to skip it. If you use the community manifest instead, the CA is not needed.

If Apple ever changes those URLs, switch `AERIAL_MANIFEST_URL` to the GitHub-hosted community set
(fewer videos, but very stable):

```
AERIAL_MANIFEST_URL=https://raw.githubusercontent.com/glouel/AerialCommunity/master/entries.json
```

## Manual Run

Fetch videos first:

```bash
AERIAL_CONFIG=/etc/aerial-signage/aerial-signage.conf /opt/aerial-signage/bin/aerial-fetch --limit 10
```

Then run the player:

```bash
AERIAL_CONFIG=/etc/aerial-signage/aerial-signage.conf /opt/aerial-signage/bin/aerial-signage
```

For non-Pi desktop testing, set:

```bash
AERIAL_MPV_GPU_CONTEXT=auto AERIAL_MPV_HWDEC=auto /opt/aerial-signage/bin/aerial-signage
```

## Troubleshooting

Black screen usually means mpv does not own DRM/KMS. Boot to console instead of desktop, run on tty1, and keep `AERIAL_MPV_GPU_CONTEXT=drm`.

If hardware decode is not active, confirm the selected quality is HEVC, `AERIAL_MPV_HWDEC=drm-copy`, and the service user belongs to `video` and `render`.

Videos are large, usually around 265-354 MB each. Use `AERIAL_VIDEO_LIMIT` or `aerial-fetch --limit N` while testing.

Logs:

```bash
journalctl -u aerial-signage
journalctl -u aerial-fetch
```
